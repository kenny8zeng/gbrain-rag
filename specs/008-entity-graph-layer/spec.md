# Feature Specification: 实体图层与文档面隔离（entity-graph-layer）

**Feature Branch**: `008-entity-graph-layer`

**Created**: 2026-09-13

**Status**: Draft

**Input**: 关联项目已把 gbrain 页直接作为"导入文档"的存储源（拆除原文档存储）。语料 13 篇含 2439 处 `[[双链]]`、413 个术语目标；生产库图谱为空（`link-sources: []`）。需要：文档面保持纯净（实体页不可见）+ 双链真正成图 + 实体间多跳可达。

## 背景与问题陈述

gbrain 只有一种对象——**页**（`pages` 表：`id` 自增整数 + `(source_id, slug)` 唯一）。文档与实体都只能是页，图的边（`links`）两端硬绑定页 id（`from_page_id`/`to_page_id`）。因此"实体节点"必须落成页，且要与"文档页"在同一库内共存——**必须显式划出两个逻辑分区，否则互相污染**。

实测确认三个具体缺陷（证据见 research.md）：

1. **图谱恒为空**：双链解析要求目标页存在（`resolveCandidateSources` 的 `allSlugs.has` 检查），不存在即 `skipped_missing_target` 丢弃。13 篇文档导入后 `links_created: 0`；补齐 413 个实体页后同一份内容产出 **997 条边**（与脚本独立核算的 uniq `(文档,目标)` 对数 997 完全一致 = 提取率 100%）。
2. **类型不可靠**：导入的 frontmatter 不含 `type`，引擎按 slug 路径推断——`docs/` 未在任何 pack 中声明 → 全部落默认值 `concept`。类型漂移导致检索面无法按类型过滤。
3. **文档面被污染**：`GET /documents` 用 `gbrain list --limit 200` 无过滤、检索 `query` 不传 `types` → 413 个实体页会混入文档列表并挤占 top-K（实测查"电池"：top-3 全为实体页 `entity|电池`、`entity|续航`、`entity|充电器`）。

## User Scenarios & Testing

### User Story 1 - 文档面纯净（Priority: P1）

作为关联项目的调用方，我通过 `GET /v1/kb/:id/documents` 列出的、以及 `/v1/kb/:id/retrieval` 检索到的，**只有我导入的文档**——自动生成的实体页对我的接口不可见、不占 top-K、不挤占列表分页。

**Why this priority**: 关联项目已把 gbrain 当文档存储源，文档面语义不得因图谱功能而改变。这是本次改造的**硬前提**。

**Independent Test**: 在一个含 13 篇文档 + 413 实体页的库里，`GET /documents` 返回条数 == 13；检索"电池"的 top-K 全部为文档页（无实体页）。

**Acceptance Scenarios**:

1. **Given** 库内有 13 篇文档与 413 个实体页，**When** 调用 `GET /v1/kb/:id/documents`，**Then** 只返回 13 条，且不含任何 `entities/` 前缀或实体类型页
2. **Given** 同上，**When** 调 `/v1/kb/:id/retrieval` 检索任一命中实体的词，**Then** 结果中零实体页；返回条数 ≤ 请求的 `top_k`
3. **Given** 文档页与实体页同名（如文档与术语都叫"电池"），**When** 检索，**Then** 只返回文档页
4. **Given** 一个实体页，**When** 调 `GET /v1/kb/:id/page?slug=<实体 slug>`，**Then** 返回 422（不属于 `docs/` 分区）——保持既有行为

### User Story 2 - 导入即建图（Priority: P1）

作为知识库使用者，我把带 `[[双链]]` 的文档导入后，**不需要任何额外手工步骤**，双链就变成了图谱的边；双链指向的术语自动拥有节点页。

**Why this priority**: 这是"图谱可用"的唯一路径——引擎不会自动创建目标页，缺这一步图谱恒为空（实测 343/997 全部丢弃）。

**Independent Test**: 空库导入一篇含 100 处双链（指向 50 个术语）的文档，完成后 `link-sources` 非空、边数 == 该文档的 uniq `(文档,目标)` 对数。

**Acceptance Scenarios**:

1. **Given** 空库，**When** 导入一篇含双链的文档且任务完成，**Then** 自动为其双链目标建立实体页，且可查到该文档的出边
2. **Given** 已存在名为"电池"的文档页（非实体），**When** 另一篇文档写 `[[电池]]`，**Then** 边指向该文档页，**不**新建同名实体页、不覆盖已有页
3. **Given** 同一目标被多篇文档双链，**When** 各文档导入完成，**Then** 该目标只有一页，入边数 == 引用它的文档数
4. **Given** 重复导入同一文档（幂等重传），**When** 任务完成，**Then** 不产生重复实体页、边数不翻倍

### User Story 3 - 实体多跳查询（Priority: P2）

作为知识库使用者，我能从一个实体出发沿关系多跳遍历（LightRAG 式"实体→实体"探索），并取得实体的聚合卡（出/入边 + 摘要）。

**Why this priority**: 关联项目的核心诉求是实体级多跳，而非仅文档召回。

**Independent Test**: 对连通实体调多跳遍历（depth≥2），返回的路径数 > depth 1 的路径数。

**Acceptance Scenarios**:

1. **Given** 实体"电池"有出边到"续航"、入边来自若干文档，**When** 以 depth=2、direction=both 遍历，**Then** 返回该实体的一跳与二跳路径
2. **Given** 某实体，**When** 查询实体卡，**Then** 返回其类型、摘要与出/入边列表
3. **Given** 跨库同名实体（两个 KB 各有"电池"），**When** 在 A 库遍历，**Then** 不返回 B 库的边（source 隔离）

### User Story 4 - 类型稳定（Priority: P3）

作为部署者，导入文档的类型由服务**显式钉定**，不依赖引擎的 slug 路径推断，也不因目录命名变化而漂移。

**Why this priority**: 类型是文档面过滤的依据；漂移会让过滤静默失效。

**Independent Test**: 导入任意文件名的文档，落库 `type` 恒为约定值。

**Acceptance Scenarios**:

1. **Given** 任意文件名的文档（含中文名、无扩展名语义），**When** 导入完成，**Then** 落库 `type` 为文档约定类型
2. **Given** 文档正文自带 `type: xxx`，**When** 导入，**Then** 服务钉定的类型生效（文档面过滤不被正文覆盖）

### User Story 5 - 实体层回收（Priority: P2）

作为知识库维护者，我删除文档（或文档更新后不再引用某术语）后，**为该文档自动创建的实体页不会永久残留**——当某个实体页不再被任何存活文档引用时，它会被自动回收；但**被其他文档共享的实体页必须保留**，且**绝不触碰用户自己创建的页**。

**Why this priority**: 实体页是导入的副产品，其生命周期必须随文档走；否则删除文档会在库里留下只增不减的垃圾页。同时这是**多租户隔离之外**的第二个正确性要求——误删共享节点会让其他文档的图断裂。

**Independent Test**: 建文档 A（含 `[[电池]]`）+ 实体页 → 删除 A → 实体页被回收；再建 A、B 都含 `[[电池]]` → 删除 A → 实体页保留（B 仍引用）。

**Acceptance Scenarios**:

1. **Given** 文档 A 是唯一引用"电池"的文档，**When** 删除 A，**Then** 自动创建的"电池"实体页被回收
2. **Given** 文档 A 与 B 都引用"电池"，**When** 删除 A，**Then** "电池"实体页**保留**（B 仍引用）
3. **Given** 用户自己创建了一页（无自动创建标记），**When** 它没有任何入边，**Then** 回收流程**不得**删除它
4. **Given** 文档 A 更新后正文不再含 `[[电池]]`，**When** 更新完成，**Then** 若无其他引用，"电池"实体页被回收
5. **Given** 建图阶段失败（提取未成功），**When** 回收流程运行，**Then** **不得**把"因提取失败而无入边"的实体页误删
6. **Given** 已回收的实体页，**When** 同一文档被重新导入，**Then** 实体页被重新创建、边恢复

## Requirements

### Functional Requirements

- **FR-001** 导入管线必须显式写入文档类型（frontmatter `type`），不依赖引擎路径推断
- **FR-002** 文档页 slug 必须保持在 `<kb>/docs/` 分区内
- **FR-003** 实体页必须落在 `<kb>/entities/` 分区（与文档分区并列，禁止根级 slug——多库同名实体互撞，实测 311 条边被 cross-source 拒绝）
- **FR-004** 实体页 slug 的尾段必须与引擎 slug 规范化算法一致（`slugifySegment` 语义：NFD→去重音→NFC→lowercase→保留字母数字/点/空格/`_`/`-`/CJK→空格转 `-`→折叠 `-`），否则双链解析不中
- **FR-005** 导入完成后，服务必须扫描该文档正文的双链目标，为**不存在**的目标建立实体页
- **FR-006** 已存在的同名文档页优先：目标已存在时不新建实体页、不覆盖
- **FR-007** 实体页建页必须幂等（重复导入同一文档不产生重复页）
- **FR-008** 建页后必须触发链接提取，使双链落成图谱边；提取必须幂等
- **FR-009** 检索（`/v1/kb/:id/retrieval`）必须按文档类型过滤，实体页不可见；**并**对返回结果做 `<kb>/docs/` 前缀兜底过滤（结构保证，不依赖类型正确性）
- **FR-010** 文档列表（`GET /v1/kb/:id/documents`）必须按文档类型过滤
- **FR-011** 检索结果必须尊重请求的 `top_k`（不超量返回）
- **FR-012** 实体页不参与向量嵌入（图查询面专用；检索面已排除，省 embed 成本与失败面）
- **FR-013** 引擎需开启按 basename 解析裸双链的开关（实体页位于子目录，实测：关 = 0 边，开 = 边成立）
- **FR-014** 管理面须提供图谱查询入口（实体卡 + 多跳遍历）
- **FR-015** 租户面不得因本次改造扩大既有能力边界（MCP 面现状保持不变，另见决策 D4）
- **FR-016** 服务自动创建的实体页必须带**来源标记**（frontmatter），用于与用户自建页区分；回收流程只处理带标记的页
- **FR-017** 删除文档后必须回收"不再被任何存活页引用"的自动创建实体页；回收前必须确认该实体页**零存活入边**
- **FR-018** 回收必须**同时**运行在：① 文档删除后；② 文档导入/更新后的建图阶段末尾（覆盖"更新后不再引用"的情形）
- **FR-019** 回收必须在**建图阶段成功之后**执行——提取失败的批次不得触发回收（否则"因提取失败而无入边"的实体页会被误删）
- **FR-020** 回收必须幂等：重复运行不产生额外删除，也不影响仍被引用的实体页

### Key Entities

- **文档页**：`slug = <kb>/docs/<name>`，`type = note`（内置类型，不会被 pack 收敛改写）；由导入管线生产
- **实体页**：`slug = <kb>/entities/<术语>`，`type = concept`（内置类型）；由导入后置阶段自动生产；正文为最小 stub，可选后续用引擎 `enrich` 填充；**必须带来源标记**（frontmatter，如 `auto_generated: wikilink-stub`）以支持回收与区分用户自建页
- **igraph 边**：`links` 表行（`from_page_id → to_page_id` + `link_type` + `link_source`），由 `extract links` 依据双链文本与目标页存在性生成；**软删文档不会级联删除这些行**（外键 `ON DELETE CASCADE` 仅在硬删时生效）

## Success Criteria

### Measurable Outcomes

- **SC-001** 13 篇文档（2439 处双链、413 个术语目标）导入后，边数 == uniq `(文档,目标)` 对数（本地实测基准 997，即提取率 100%）
- **SC-002** `GET /documents` 返回条数 == 文档数（不含实体页）
- **SC-003** 检索 top-K 中实体页占比 == 0；返回条数 ≤ `top_k`
- **SC-004** 重复导入幂等：第二次导入后页数与边数不变
- **SC-005** 以实体为起点 depth=2 多跳返回路径非空
- **SC-006** 关联项目既有 5 项验收全部通过（写/删/URL/图片/覆盖度），即"文档面语义零变化"
- **SC-007** 删除文档后，其独占引用的实体页被回收；页数回到删除前减去该文档与其独占实体页
- **SC-008** 共享实体页在任一引用文档被删除后仍存在（入边数 == 剩余引用文档数）
- **SC-009** 回收流程对无标记的用户页零副作用（构造反例验证：孤儿用户页不被删除）

## Assumptions

- 单实例部署（多副本不在本期范围）
- 实体页生成的术语目标规模为百量级（13 篇 → 413 个）；万级语料需要批量化与阈值策略（见 plan 决策 D2）
- 关联项目主路径为 HTTP 文档 API（`/v1/kb/*`），非直连 MCP
- 引擎版本固定 v0.47.6.0；`by-mention` 自动实体识别不在本期范围（语料已显式写双链）
