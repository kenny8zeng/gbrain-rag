# Feature Specification: 裸文档解析 API（对外复用解析能力）

**Feature Branch**: `009-document-parse-api`

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "增加对外提供裸文档解析的能力：对外提供裸文档解析API，让集成本项目的应用端可以复用本项目的文档解析能力实现其它功能；裸文档解析API统一根据项目部署设定 anydoc 与 docling 之间的优先级来解析文档；如果项目部署未设定 docling，则 anydoc 能力支持外的文件类型返回不支持的文件类型"

## Clarifications

### Session 2026-09-20

- Q: 调用方使用裸解析端点时，需要出示什么级别的凭证授权？ (FR-010) → A: 仅需凭证有效（任何有效钥匙都可用），不要求绑定任何知识库授权
- Q: 裸解析端点是否接受纯文本类输入（`.md` / `.txt`）？ → A: 接受；文本内容原样返回（标记为直通，零解析开销），非文本才交给解析通道
- Q: 裸解析端点是否接受网页地址（URL）作为输入？ → A: 接受，但该能力归属外部解析服务（URL 最终由其处理）：部署已配置则可解析，未配置则按需求第 3 条返回「不支持的类型」并指引所需配置

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 应用端复用解析能力转换单个文档 (Priority: P1)

集成本服务的应用（如对话 Agent、内容审核工具、批量迁移脚本）持有一份非 Markdown 文档（PDF/DOCX/PPTX/XLSX/CSV/EPUB/RTF/ODT 等），希望拿到与知识库导入**完全一致**的 Markdown 结果用于自己的下游处理（抽字段、二次分块、送入自有 LLM 流程），但不希望把这些内容写进任何知识库。调用方上传文件，同步拿到 Markdown 正文与解析路径信息（实际生效的解析器、耗时、字符数）。

**Why this priority**: 这是需求的核心价值——把本项目已具备的解析能力变成可被其它系统复用的对外契约。没有它，集成方只能重复实现解析或被迫把文档塞进知识库再取回（污染数据、浪费嵌入配额）。

**Independent Test**: 上传一个 DOCX 文件到解析端点，断言响应包含 Markdown 正文、解析器标识与耗时；断言该请求**没有**在任何知识库中产生页面（对比调用前后知识库页面数不变）。

**Acceptance Scenarios**:

1. **Given** 部署同时具备两套解析能力且首选为任一解析器，**When** 调用方上传受支持的文档，**Then** 返回 Markdown 正文 + 实际生效的解析器标识 + 耗时，且不写入任何知识库
2. **Given** 部署未配置外部解析服务（仅内置解析能力），**When** 调用方上传内置能力支持的文档，**Then** 正常返回 Markdown，解析器标识为内置能力
3. **Given** 调用方上传空文件或损坏文件，**When** 请求被处理，**Then** 返回明确的失败原因（不是超时或空响应），且不产生副作用
4. **Given** 调用方上传纯文本文件（`.md`/`.txt`），**When** 请求被处理，**Then** 内容原样返回并标记为直通路径，且不触发任何解析通道

---

### User Story 2 - 解析器优先级由部署设定统一决定 (Priority: P2)

运维按部署环境设定解析器优先级（首选哪套、是否配置外部解析服务）。所有解析请求——无论是知识库导入还是对外裸解析——都必须遵循同一套优先级与回退规则，不允许调用方在请求里覆盖。这样集成方的解析结果与知识库内容保持一致，运维也只需在一处调整策略。

**Why this priority**: 保证「同一份文档，导入知识库与单独解析得到同样的 Markdown」这一致性契约；同时让解析策略保持运维可控、避免调用方引入不一致的解析路径。

**Independent Test**: 在同一部署下，用同一文件分别走知识库导入与裸解析端点，断言两者产出的 Markdown 正文一致、且报告的生效解析器相同；再改变部署的优先级设定重启，断言两个入口的生效解析器**同时**变化。

**Acceptance Scenarios**:

1. **Given** 部署设定了首选解析器，**When** 同一文件分别走导入与裸解析两条路径，**Then** 两者 Markdown 正文一致且报告同一个生效解析器
2. **Given** 部署首选解析器不可用（解析失败），**When** 调用方请求解析，**Then** 按部署的回退设定尝试备用解析器，并在响应中如实报告最终生效者
3. **Given** 调用方在请求中携带任何形式的解析器偏好，**When** 请求被处理，**Then** 该偏好被忽略，仍按部署设定解析
4. **Given** 调用方提交网页地址，**When** 部署已配置外部解析服务，**Then** 由该服务完成转换并如实报告其为生效解析器

---

### User Story 3 - 部署未配置外部解析服务时明确拒绝不支持的类型 (Priority: P3)

部署未配置外部解析服务时，解析能力收窄。调用方上传内置能力覆盖范围之外的文件类型（如独立图片）、或需要外部解析服务独有能力（如网页地址）时，必须收到**明确的不支持类型错误**（指出该类型、并说明原因），而不是静默失败、空结果或通用 500。调用方据此决定自行转换或放弃。

**Why this priority**: 集成方需要可编程判断「这个类型在当前部署下能不能解析」，才能构建可靠的降级路径；模糊失败会让集成方误判为临时故障而反复重试。

**Independent Test**: 在未配置外部解析服务的部署上，上传内置能力不支持的类型，断言返回专用错误码与可读说明；再看服务日志确认没有触达外部解析服务。

**Acceptance Scenarios**:

1. **Given** 部署未配置外部解析服务，**When** 调用方上传内置能力不支持的类型（纯文本类除外），**Then** 返回专用的「不支持的文件类型」错误（含类型与原因），且不触发任何外部调用
2. **Given** 部署未配置外部解析服务，**When** 调用方请求需要外部能力的输入（如网页地址），**Then** 返回同样的不支持类型错误并指引所需配置
3. **Given** 部署已配置外部解析服务，**When** 调用方上传内置能力不支持但外部能力支持的类型**或提交网页地址**，**Then** 解析成功（不再是「不支持」），且报告生效解析器为该外部服务

---

### Edge Cases

- **文件大小超限**：调用方上传超过部署上限的文件 → 明确的超限错误（含上限值），不进入解析
- **文件名无扩展名或扩展名误导**：类型判定**以内容嗅探优先**（与解析通道自身一致），扩展名仅在内容无法识别时回退；扩展名不可识别但内容为纯文本类 → 按直通处理（不得误报不支持）；内容与扩展名均不可判定 → 「不支持的文件类型」
- **首选解析器不可用但回退可用**：必须回退成功并如实报告生效者（不得因首选失败直接报错）
- **两套解析能力同时失败**：返回聚合的失败原因（两个通道各自的失败摘要），不泄露内部堆栈
- **网页地址在未配置外部解析服务时**：必须立刻返回「不支持的类型」（含所需配置指引），不得尝试自行抓取、不得静默返回空正文
- **并发请求**：多个调用方同时请求解析时，解析负载不得让知识库导入/检索不可用；解析通道自身达到并发上限时应返回可重试错误而非排队至超时
- **解析结果为空**：文档可解析但正文为空 → 返回成功但明确标记内容为空，调用方自行判断（不得伪装成失败）
- **纯文本直通为零解析成本**：`.md`/`.txt` 输入不得触发解析通道（不得因外部解析服务不可用而失败，也不得消耗解析并发额度）
- **超长文档**：解析耗时超过部署单次解析上限 → 明确的超时错误，不挂起连接
- **并发请求互不干扰**：同一文件被并发解析时结果不互相影响（本特性**不落盘**，输入仅内存传递，故不存在文件冲突面）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 对外提供独立的解析端点，接收单个文档并返回 Markdown 正文，**不写入任何知识库**、不消耗嵌入配额、不产生页面/图谱数据
- **FR-002**: 解析端点 MUST 按**部署级**解析器优先级设定（首选解析器 + 是否配置外部解析服务 + 回退策略）选择解析通道，与知识库导入路径使用**同一套**决策逻辑
- **FR-003**: 解析端点 MUST 忽略请求中任何形式的解析器偏好（解析策略不可由调用方覆盖，保持运维统一可控）
- **FR-004**: 响应 MUST 报告本次实际生效的解析路径标识（具体解析器，或纯文本直通）、解析耗时与正文字符数，供调用方审计与性能监控
- **FR-005**: 系统 MUST 接受纯文本类输入（`.md` / `.txt`）并**原样返回其内容**（在响应中标记为直通路径，不进入任何解析通道）；其中 **`.md` 与知识库导入的 md 直通语义一致**，**`.txt` 为本端点对调用方的便利扩展**（导入路径对 `.txt` 会送解析链并因无法识别格式而失败，本端点改为直通）——该差异为**有意设计**，须在能力自描述与文档中声明；非文本输入才交给解析通道
- **FR-005a**: 部署未配置外部解析服务时，系统 MUST 对内置解析能力覆盖范围之外的文件类型返回**专用的「不支持的文件类型」错误**，并在消息中指明该类型与原因；纯文本类输入永不落入该错误
- **FR-006**: 系统 MUST 接受网页地址作为输入，且该能力**归属外部解析服务**（URL 最终由其转换）；部署未配置外部解析服务时 MUST 返回专用的「不支持的类型」错误并指引所需配置，且实施该判定时 MUST NOT 触达任何外部解析服务（本条的触发条件与 FR-005a 并列：FR-005a 覆盖「文件类型超出内置能力范围」，本条覆盖「输入形式需要外部能力」，两者都返回不支持类错误但错误码不同）
- **FR-007**: 回退语义 MUST 与导入路径一致：首选通道失败且部署允许回退时，自动尝试备用通道；响应如实报告最终生效的解析器；两通道皆失败时返回聚合原因
- **FR-008**: 系统 MUST 按文件真实内容判定类型（内容优先、扩展名回退），并据此判定是否在能力覆盖范围内
- **FR-009**: 系统 MUST 对超过部署上限的文件返回明确的超限错误（含上限值），在进入解析前拒绝
- **FR-010**: 解析端点 MUST 仅要求**有效凭证**（复用现有租户凭证体系与校验路径）——不要求凭证绑定任何知识库、请求也不指定知识库；未通过校验的请求返回与现有端点一致的错误语义（无效与不存在同等响应，不泄露资源存在性）
- **FR-011**: 解析请求的处理 MUST NOT 挤占知识库导入/检索所依赖的引擎并发容量（解析不经该容量通道）；同时解析通道自身 MUST 有并发上限，饱和时返回可重试错误，不得使导入/检索因解析负载不可用
- **FR-012**: 解析请求 MUST NOT 影响知识库状态：调用前后任何知识库的页面数、图谱边数、任务记录均不变
- **FR-013**: 解析失败 MUST 返回结构化错误（稳定错误码 + 可读消息），失败原因分类包括：不支持类型、超限、解析失败（含双通道失败摘要）、超时；不得返回未处理的内部异常
- **FR-014**: 系统 MUST 提供解析能力自描述信息（当前部署生效的首选解析器、可用通道、各通道覆盖的文件类型范围），使调用方能预先判断某类型是否可解析

### Key Entities *(include if feature involves data)*

- **解析请求（Parse Request）**：一次对外解析调用；属性含输入文件（字节 + 文件名）、调用方凭证、部署级解析策略（只读）。**不持久化**。
- **解析结果（Parse Result）**：一次解析的产出；属性含 Markdown 正文、生效解析器标识、耗时、正文字符数、内容是否为空。
- **解析能力描述（Parser Capability Profile）**：部署级只读视图；含当前首选解析器、可用通道集合、每通道支持的文件类型范围。
- **解析失败（Parse Failure）**：结构化失败；属性含分类码（不支持类型 / 超限 / 解析失败 / 超时）、可读消息、可选的双通道失败摘要。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 集成方可用一次请求把受支持的文档转成 Markdown，无需自行部署解析组件，也无需把内容写入知识库，且**无需事先创建/绑定任何知识库**（以仅持有效凭证即可成功、且调用前后知识库页面数/图谱边数/任务记录数均不变为验收依据）
- **SC-002**: 对于**导入与裸解析两路都能处理的输入**（即 `.md` 与解析通道覆盖的文档类型），同一文件经两条路径产出的 Markdown 正文完全一致，且两条路径报告的生效解析器相同（以逐字节比对为验收依据）；`.txt`（仅裸解析支持，见 FR-005）不在本条适用范围内
- **SC-003**: 部署未配置外部解析服务时，100% 的能力范围外请求（内置不支持的文件类型 + 网页地址）返回专用「不支持的类型」错误（纯文本类输入除外，其成功率 100%），且其中 0 次触达外部解析服务（以错误码断言 + 外部服务零调用为验收依据）
- **SC-004**: 调用方可在收到错误后程序化区分「类型不支持（不该重试）」与「容量/超时（可重试）」，两条路径的错误码集合互不重叠
- **SC-005**: 变更部署解析优先级设定（含外部解析服务地址的有无）并重启后，导入与裸解析两个入口的生效解析器、以及网页地址的可解析性在同一时刻改变（以两入口的一致性断言 + URL 能力翻转断言为验收依据）
- **SC-006**: 并发解析请求进行期间，知识库导入与检索端点保持可用（以并发期间导入/检索请求全部得到成功或可重试响应、无不可用错误为验收依据）
- **SC-007**: 调用方可在解析前通过能力自描述信息判断目标类型在当前部署是否可解析，判断正确率 100%（以覆盖范围内/范围外各类型样本的判定一致性为验收依据）

## Assumptions

- **解析能力复用而非新增**：本特性复用现有解析能力与优先级配置（部署级首选解析器、外部解析服务地址、回退语义），不引入新的解析器实现或新的优先级维度
- **同步返回**：解析在单次请求内同步完成（调用方需要正文才能继续处理），不引入任务队列轮询模型
- **单文件或单个网页地址**：一次请求处理一个文档，或一个网页地址（URL 能力归属外部解析服务、随部署配置而变）；不支持归档或批量（批量导入已有独立特性）
- **凭证模型（已澄清）**：复用现有租户凭证的校验路径，仅要求凭证**有效**，不要求绑定知识库、请求亦不指定知识库（见 Clarifications）。该选择保证集成方无需为纯解析先建库发钥匙，同时不引入新的权限概念
- **不持久化输入与产出**：解析的输入文件与产出正文不落库、不被检索；仅使用请求期临时存储并在请求结束后清理
- **不改变现有导入行为**：知识库导入路径的既有语义（解析优先级、回退、错误码）保持向后兼容
- **能力范围以现有实现为准**：各解析通道支持的文件类型集合沿用现有定义，不在本特性中扩展
- **纯文本直通（已澄清）**：`.md`/`.txt` 原样返回、不经解析通道（见 Clarifications）；该路径与知识库导入的纯文本直通保持一致，使集成方可用单一入口处理全部文本类语料
- **部署上限沿用**：文件大小、超时等约束复用现有部署配置项，不为本特性新增独立配置
- **凭证明文安全**：沿用现有凭证安全约定（不记录正文内容到日志，避免文档内容泄露）

## Out of Scope

- 解析结果的持久化、去重、版本管理（本特性只做「进来 → 出去」的转换）
- 批量/归档解析（已由批量导入特性覆盖）
- 新增解析器能力或扩展任一通道的类型支持范围
- 网页抓取的合规/内容审查（沿用现有实现边界）
- 调用方自定义解析参数（如 OCR 开关、分块策略）——若后续需要再单独评审
