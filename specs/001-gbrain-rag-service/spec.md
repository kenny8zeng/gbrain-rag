# Feature Specification: GBrain 核心 RAG 知识库服务

**Feature Branch**: `001-gbrain-rag-service`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "评估以上对话对项目需求的讨论是否还有不明确的" —— 即：基于前期需求讨论（以 GBrain 为知识库核心的 RAG 服务）撰写正式特性规格，并识别残余不明确点。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员创建知识库并管理 Agent 授权 (Priority: P1)

平台管理员创建一个知识库（底层为独立的知识分区），随后为某个 AI Agent 签发访问凭证：指定该 Agent 唯一的内容写入分区，以及事前审批通过的若干个可检索分区（读授权组合）。凭证明文仅在签发时返回一次。管理员可以随时变更授权组合或吊销凭证。

**Why this priority**: 没有分区与授权，一切内容管理与检索都无从谈起；多 Agent 的越权防护是该服务的核心价值。

**Independent Test**: 创建两个知识库、签发一枚"写 A 读 A,B"的凭证，验证 Agent 只能写 A、检索同时覆盖 A 与 B、完全看不到其他分区，即可独立交付价值。

**Acceptance Scenarios**:

1. **Given** 系统已初始化，**When** 管理员创建名为"产品文档"的知识库，**Then** 系统返回知识库标识，且该知识库处于空状态、可被凭证引用。
2. **Given** 存在知识库 A 与 B，**When** 管理员签发凭证 {写=A, 读=[A,B]}，**Then** 系统返回一次性明文凭证，后续请求中凭证可用。
3. **Given** 凭证 {写=A, 读=[A,B]} 已签发，**When** 使用该凭证请求检索 C（未授权知识库），**Then** 系统拒绝并明确提示无权限。
4. **Given** 凭证已签发，**When** 管理员变更其读授权为 [A] 后立即用旧组合请求，**Then** B 的内容不再出现在结果中。
5. **Given** 凭证已签发，**When** 管理员吊销该凭证，**Then** 该凭证随后的任何请求立即被拒绝。

---

### User Story 2 - 应用导入多来源文档并建立检索索引 (Priority: P1)

业务应用向指定知识库提交待入库内容，支持四种输入：常见文档文件（PDF、Office 等）、图片文件（转为文字描述与 OCR 内容）、网页 URL（抓取正文）、Markdown 纯文本（直接入库）。提交后立即返回任务标识，后台异步完成"格式转换 → 规范化 → 单文档单页面入库 → 建立检索索引"；应用可随时查询任务进度，失败任务附带可读的失败原因并自动重试。

**Why this priority**: 内容是 RAG 的燃料；没有可靠的导入管道，检索无从发生。

**Independent Test**: 向空知识库提交一份 PDF 与一个网页 URL，轮询至任务完成，随后检索命中其中内容，即验证了完整管道。

**Acceptance Scenarios**:

1. **Given** 空知识库与有效凭证，**When** 提交一份 PDF 文件，**Then** 立即返回任务标识（接受确认），任务最终到达成功终态且页面可检索。
2. **Given** 同一凭证，**When** 提交一个公网网页 URL，**Then** 任务成功且页面内容与网页正文一致（含来源标注）。
3. **Given** 同一凭证，**When** 提交一张含清晰文字的图片，**Then** 任务成功且页面包含图片中的文字内容。
4. **Given** 同一凭证，**When** 直接提交 Markdown 文本，**Then** 任务成功且内容原样入库（不经外部转换服务）。
5. **Given** 转换服务暂时不可用，**When** 提交一份 PDF，**Then** 任务自动重试；重试耗尽后任务标记失败并给出原因。
6. **Given** 使用仅含读授权（无写分区）的凭证，**When** 提交任何导入请求，**Then** 系统拒绝。

---

### User Story 3 - Agent 经标准协议管理单分区内容并跨分区检索 (Priority: P1)

AI Agent 通过标准 MCP 协议接入服务：在其唯一写分区内完成页面内容的增删改查、打标签等基础内容管理；检索时系统自动在其全部已授权读分区内合并查找，无需 Agent 指定分区，也无法通过任何请求参数触达未授权分区。

**Why this priority**: 这是"AI Agent 自主维护与消费知识"的核心场景，也是授权模型的最终验证面。

**Independent Test**: 用一枚 {写=A, 读=[A,B]} 凭证建立 MCP 会话，写入页面、检索跨源命中、尝试越权读写均被拒，即为可交付切片。

**Acceptance Scenarios**:

1. **Given** 有效 MCP 凭证，**When** Agent 在其写分区创建页面，**Then** 页面落库且立即可被该 Agent 检索。
2. **Given** 读授权覆盖 A 与 B 且两库各有一篇相关内容，**When** Agent 发起一次语义检索，**Then** 结果同时包含来自 A 与 B 的条目（自动跨源合并）。
3. **Given** 同一凭证，**When** Agent 请求访问未授权分区 C 的任何内容，**Then** 结果为空或被拒，绝无 C 的数据泄露。
4. **Given** Agent 尝试写入其写分区前缀之外的页面标识，**Then** 写入被拒绝。

---

### User Story 4 - 应用统一检索接口 (Priority: P2)

业务系统不经过 Agent，直接以 REST 方式对授权知识库执行检索：支持语义混合检索与关键词检索两种模式，可指定返回条数；结果包含页面标识、片段文本与相关度得分，可直接用于生成式问答的上下文组装。

**Why this priority**: 多数存量应用只说 HTTP，统一检索接口决定服务能否被集成。

**Independent Test**: 向已导入内容的知识库发起检索请求，断言命中内容与返回元数据完整。

**Acceptance Scenarios**:

1. **Given** 知识库已导入含"退货政策"的文档，**When** 应用检索"退货规则"，**Then** 返回结果首条命中该内容并附带得分与来源。
2. **Given** 凭证读授权为 [A,B]，**When** 分别对 A、B 发起检索，**Then** 均成功；对 C 发起则被拒。

---

### User Story 5 - 管理员执行知识引擎高级运维 (Priority: P2)

管理员通过统一的低层管理接口执行知识引擎的全量高级操作（分区运维、后台作业、系统健康、凭证管理等），输出默认为可读的流式文本，状态查询类操作可要求结构化结果；破坏性操作在接口描述中显式标注。

**Why this priority**: 运维逃生通道，保证不因服务层功能缺失而无法管理引擎；重要性低于核心业务流。

**Independent Test**: 经管理接口执行一次健康检查（结构化）与一次分区列表，均返回正确数据。

**Acceptance Scenarios**:

1. **Given** 管理员令牌，**When** 请求知识引擎健康状态（结构化模式），**Then** 返回可解析的状态数据。
2. **Given** 管理员令牌，**When** 以默认模式执行引擎命令，**Then** 获得流式输出且可观察到执行结束状态。
3. **Given** 无效令牌，**When** 访问任何管理接口，**Then** 全部被拒绝。

---

### User Story 6 - 导入任务可观测 (Priority: P3)

管理员与应用可查询导入任务列表与详情（按知识库、状态过滤），获得每项任务的当前状态、尝试次数与失败原因；服务输出结构化运行日志覆盖关键操作。

**Why this priority**: 运维可观测性保障，依赖 Story 2 存在。

**Independent Test**: 提交若干导入任务后查询任务列表，断言状态与详情一致。

**Acceptance Scenarios**:

1. **Given** 已有成功与失败任务各一，**When** 按状态过滤查询，**Then** 列表准确分类且失败项含原因。

### Edge Cases

- 提交的文件超过大小上限或为不支持的格式 → 明确拒绝并列出支持范围
- 提交的 URL 不可达、非 HTML、或指向内网/受限地址 → 任务失败并说明原因；受限地址按网络策略拦截
- 同一文档重复提交 → 按"重复导入语义"（见 FR-008）处理
- 转换服务超时或返回异常内容（如空转换结果）→ 任务失败带原因，不产生半成品页面
- 知识库被删除（归档）后其凭证的引用 → 相关请求返回明确的"知识库不可用"而非模糊错误
- 检索词为空串或超长 → 参数校验拒绝
- 知识引擎或转换服务不可用时服务整体的行为 → 管理接口返回降级状态，导入任务排队或失败，检索返回明确错误

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许管理员创建知识库，每个知识库对应后端知识引擎中一个完全独立的数据分区（页面、索引、文件互不可见）。
- **FR-002**: 系统必须允许管理员查看知识库列表与详情（含页数、索引覆盖度、最近活跃时间），并以"归档→限时保留→永久清除"的两阶段流程删除知识库。
- **FR-003**: 系统必须允许管理员签发 Agent 凭证，凭证定义包含：唯一标签、至多一个写分区、零或多个读分区（事前审批组合）；凭证明文仅在签发响应中返回一次，系统仅存哈希。
- **FR-004**: 系统必须保证 Agent 经 MCP 协议的内容管理操作只落其写分区，且写分区之外的页面标识写入被拒。
- **FR-005**: 系统必须保证检索范围等于该凭证的读分区组合，跨分区结果自动合并；任何请求参数都不能扩大检索范围。
- **FR-006**: 凭证授权组合的变更必须即时生效；凭证吊销必须使所有后续请求立即失效。
- **FR-007**: 系统必须支持四种导入输入：文档文件（含图片）、网页 URL、Markdown 直传；导入为异步任务，提交即返回任务标识。
- **FR-008**: 重复导入同一文档（派生页面标识相同）时，系统必须覆盖更新既有页面（upsert），版本历史由知识引擎保留以支持回滚；任务结果必须标明本次为"新建"还是"更新"。
- **FR-009**: 导入管道必须按"外部转换服务转换（文档/图片/URL）→ 元数据规范化 → 单文档单页面入库 → 建立检索索引"执行；除 Markdown 直传外均须经转换服务；任务失败自动重试（有限次）并记录最终原因。
- **FR-010**: 系统必须允许凭证持有者对其授权分区执行检索，支持语义混合与关键词两种模式及返回条数限定；检索结果必须包含页面标识、片段与相关度得分；结果重排序由知识引擎的配置决定（服务方透传配置，不自行实现）。
- **FR-011**: 系统必须向管理员暴露知识引擎全量高级操作的统一代理接口；默认流式文本输出，状态查询类操作支持请求结构化结果；破坏性操作必须显式标注。
- **FR-012**: 系统必须对全部接口鉴权：管理面用管理员令牌，租户面用 Agent/应用凭证；跨权访问必须拒绝且不带被拒资源的存在性信息。
- **FR-013**: 网页 URL 导入不做地址校验与访问限制（完全放开，由调用方保证输入可信）；该策略仅适用于与敏感内网隔离的受信部署环境，部署文档必须显著标注 SSRF 风险。
- **FR-014**: 系统必须记录结构化运行日志（请求、任务生命周期、凭证事件），支持按凭证标识追踪行为。
- **FR-015**: 单文件导入必须受大小上限约束（默认 100MB，部署方可调整）；超限请求明确拒绝并提示上限值。

### Key Entities *(include if feature involves data)*

- **知识库（知识分区）**: 内容的顶层隔离单元；属性：标识、名称、页数、索引覆盖度、状态（活跃/归档/已清除）。
- **Agent 凭证**: Agent 或应用的唯一身份；属性：标签、写分区（0/1）、读分区列表、状态（有效/吊销）；凭证与上游引擎凭证一一对应。
- **导入任务**: 一次内容导入的异步执行记录；属性：目标知识库、输入类型（文件/URL/文本）、状态（排队/执行/成功/部分成功/失败）、尝试次数、失败原因、产出页面标识。
- **页面**: 知识库内的最小内容单元，由导入或 Agent 写入产生；属性：标识、标题、标签、内容、版本历史。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 常规文档（≤50 页 PDF）从提交到可检索的端到端耗时 ≤ 5 分钟（P95）。
- **SC-002**: 检索请求（含跨分区）响应时间 P95 ≤ 2 秒。
- **SC-003**: 隔离性验证：以未授权分区为目标的任何读取尝试，泄露率为 0（双源对照测试全通过）。
- **SC-004**: 服务规模能力：支持 ≥20 个知识库、单库 ≥1 万篇文档、10 路并发检索，且在满载时 SC-001/SC-002 时延指标不劣化。
- **SC-005**: 管理员首次完成"建库→发凭证→导入→检索"全流程操作时间 ≤ 10 分钟。
- **SC-006**: 100% 的导入任务有明确终态；失败任务 100% 附带可读原因。
- **SC-007**: 管理员通过统一管理接口可完成知识引擎既有全部运维操作，无需登录引擎本体。

## Assumptions

- 部署形态为单实例单体服务 + 独立的关系数据库 + 独立部署的文档转换服务（Docling 实例）+ 知识引擎（GBrain）；不做高可用多活。
- 评估用的既有 GBrain 容器与本项目无关；生产环境重新部署并持久化数据。
- 图片导入质量取决于转换服务端的识别管线配置，服务方仅透传；embedding 与 rerank 均由知识引擎侧配置提供。
- 已确认决策（2026-08-31 澄清）：规模目标为小规模（≤20 知识库、每库 ≤1 万文档、10 并发检索）；URL 导入完全放开、不做地址校验（仅限受信隔离部署环境，SSRF 风险由部署边界承担）；重复导入为覆盖更新（upsert，版本历史兜底）；文件大小上限默认 100MB（部署可调）。其余未竟事项均取上述默认值。
- 知识库删除采用引擎原生的 72 小时归档保留期，到期由管理员显式清除。
- MCP 工具面默认为精简集（内容管理 + 检索），可按凭证收窄。
- 服务全部接口走统一入口单端口，管理面与租户面仅以鉴权区分，不做网络层隔离。

## Dependencies

- GBrain 知识引擎（v0.47+）：分区管理、页面存储、混合检索、MCP 服务、凭证与授权（federated-read 语义已在 v0.47.6.0 实证）。
- 独立部署的 Docling 文档转换服务（v1.30+）：文档/图片/网页 → Markdown 转换能力。
- Postgres（含向量扩展）作为知识引擎的数据引擎。
- OpenAI 兼容的 embedding 服务（可选 rerank 服务）用于向量检索。

## Out of Scope

- 自助申请/审批门户（管理面 API 即审批入口）
- 服务方自行实现 rerank 或文档分块（分块由知识引擎负责）
- 高可用多活部署、多租户计费
- 导入完成回调/Webhook 通知
- 评估环境容器迁移（评估容器仅作行为验证基准）
