gbrain-rag 设计文档

日期 2026-08-31 ｜ 状态 待评审 ｜ 技术栈 Bun + TypeScript ｜ 相关 gbrain v0.47.6.0 · cli2api · docling-serve v1.30.0

0背景与目标

以 GBrain 为知识库核心构建 RAG 知识库服务，统一暴露所有对外接口：

  • 知识分区（KB）映射 gbrain source；API 驱动自动供给（建分区、发凭证）。
  • AI Agent 经本服务 MCP 网关完成单写分区的内容管理与跨分区检索（组合事前审批）。
  • 管理面集成 cli2api（作为库）：gbrain CLI 全量操作 → REST。
  • 文档摄取：PDF/Office/图片/网页 URL → docling 转 MD → gbrain 页面 → 建索引。
  • 部署：gbrain-rag + cli2api（库）+ gbrain 打包进一个镜像；Postgres 与 docling 独立部署。评估用的现有 gbrain 容器与本工程无关。
非目标（v1）：自助申请/审批门户（管理面 API 即审批入口）；自建 rerank 逻辑（gbrain 原生支持可选 rerank 模型，环境变量透传配置即可）；docling chunking（分块由 gbrain 负责）；计费多租户。

1.1 上游凭证模型（关键决策）

gbrain 的分区隔离绑定在凭证上而非请求参数上（auth register-client --source / --federated-read / --bound-slug-prefixes / --surface）。共享上游连接无法按请求钉定 source，单凭证代理 MCP 会跨分区泄数据。

因此采用双通道凭证：

通道凭证分区隔离方式
CLI 通道（管理 / REST 检索 / 摄取写入）单 admin 凭证逐调用 --source 或 GBRAIN_SOURCE 环境变量钉定，网关代码保证不透传调用方可控的 source 选择
MCP 通道（Agent 网关代理）每 agent key 一枚上游 OAuth client（client_credentials）gbrain 侧硬隔离：写分区唯一（--source）+ slug 前缀栅栏 + 读授权 --federated-read 列表，详见 1.2 节

agent key 签发即注册上游 client；授权组合变更走 auth rescope-client；吊销 key 同步 auth revoke-client。上游 access token（TTL 1h）由网关缓存并在过期/401 时刷新。

1.2 Agent 授权关系（已在 gbrain v0.47.6.0 实证）

  • 1 agent key = 1 上游 OAuth client。写分区唯一（注册时 --source 指定），并以 --bound-slug-prefixes <source>/* 栅栏所有 slug 写操作——MCP 内容管理只落写分区。
  • 读授权 = --federated-read 列表。检索类工具（search/query/think 等）默认检索范围即该列表覆盖的 source 集合，自动跨源合并结果。实测：federated-read [probe-a,probe-b] 客户端一次 search 同时命中两源页面；仅授权 probe-a 的对照组完全不可见 probe-b。
  • 请求级不可越权：v0.34 起 --source-id 对 remote caller 不能超出 grant 范围（__all__ 等同省略）。网关层面同样不透传调用方可控的 source 选择，双重约束。
  • 生命周期联动：审批组合变更 → auth rescope-client 即时生效；吊销 → auth revoke-client（token 级联清除，已实证）。
  • source 的 federated 标记（sources add --federated）只影响 grantless 本地默认搜索，与 OAuth client 的读授权无关，本项目不依赖。

3统一路由（单端口，默认 3000）

3.1 管理面 Bearer ADMIN_TOKEN

路由行为
POST /v1/kb建知识库：建 DATA_DIR/brains/<kbId>/（git init + 首提交）→ sources add kb-<id> --path <dir>
GET /v1/kb · GET /v1/kb/:idsources list / status 映射（页数、embed 覆盖、陈旧度）
DELETE /v1/kb/:idsources archive（72h 保留期）；联动吊销引用它的 agent key 上游 client。物理清除 purge 单独接口
POST /v1/keys签发 agent key：{label, write_kb?, read_kbs[]} → 按组合注册上游 OAuth client（写分区 --bound-slug-prefixes 栅栏；纯读 --scopes read）→ 返回明文 API key（仅此一次，库存哈希）
PATCH /v1/keys/:id审批组合变更 → auth rescope-client 同步上游
DELETE /v1/keys/:id吊销 API key + 上游 client
GET /v1/jobs · GET /v1/jobs/:id摄取任务查询（按 kb/status 过滤）
/v1/admin/gbrain/*cli2api gbrain 55 路由代理（默认 SSE 流式）：sources、jobs、admin、auth、storage 等全量 CLI 面；只读状态类路由支持 ?format=json（见下方影响分析）
SSE 非结构化输出影响分析：现有 clis/gbrain.yaml 未暴露 --json，代理输出为 CLI 人类可读文本的 SSE 流，程序化消费脆弱。影响面仅限此逃生通道——gbrain-rag 自有 REST（kb/keys/jobs/retrieval/documents）内部直接以 --json 调用 CLI 并解析，输出结构化，不受影响。对策：vendored cli2api 扩展 x-cli.jsonArg 机制，对标注的只读状态类路由（sources list/status、jobs list/get/stats、stats、health、features 等）支持 ?format=json：runner 追加 JSON flag、缓冲 stdout、返回单次 JSON 响应（解析失败 502 附 raw text）；其余路由维持 SSE 流式，长任务进度可见性不变。

3.2 租户面 X-API-Key

key 即 agent 身份，携带 write_kb（0/1 个）与 read_kbs（事前审批的列表，可含其它 KB）。跨权访问一律 403，不存在请求级 source 参数。

路由行为
POST /v1/kb/:id/documents导入：multipart 文件（文档/图片，docling 转 MD）| {url}（网页抓取转换）| text/markdown 直传（跳过 docling）。导入是写操作，校验 id = key.write_kb；建 job → 202 {job_id}
GET /v1/kb/:id/documents页面列表（gbrain list --json，GBRAIN_SOURCE 钉定）
DELETE /v1/kb/:id/documents/:slug删页面（gbrain delete），需 id = key.write_kb；原始文件同步删除
GET /v1/kb/:id/documents/jobs/:jobId任务状态 / 进度 / 错误详情
POST /v1/kb/:id/retrieval{query, mode?: hybrid|keyword, top_k?} → gbrain query / search --json（admin 凭证 + 逐调用钉定）→ 规范化 JSON；rerank 由 gbrain 侧配置生效，网关不自行实现
POST|GET /mcpStreamable HTTP MCP 网关：API key → 取该 key 上游 client 凭证（缓存/刷新）→ 代理 gbrain serve --http；剥离调用方自带 Authorization 头；--surface 每上游 client 钉定（默认 starter，env 可调）

GET / 服务信息；GET /openapi.json、GET /docs 聚合 Swagger UI（RAG REST + gbrain admin spec）。

4摄取管道（异步 worker）

自建 rag_jobs 表驱动（不兼容 gbrain Minions：其内置 job 类型无法承载自定义 docling 任务）。单进程内 worker loop 轮询认领，UPDATE ... WHERE status='queued' 原子认领，进程重启后 running 超时任务回收重跑。

步骤动作失败处理
1 取件文件：multipart 已落盘 DATA_DIR/incoming/；URL：网关预校验 scheme/host 白名单后原样登记登记即校验，4xx 直接 400
2 转换文件/图片 → docling POST /v1/convert/file；URL → POST /v1/convert/source；md 直传类型跳过本步与步骤 3。worker 内异步等待（timeout 600s）；docling 自带并发管理，不用其 async/poll 端点4xx/5xx → job failed 带原因；重试 3 次指数退避
3 规范化frontmatter 注入 title / kb / source_file|source_url / converted_at—
4 写入原始文件移入 DATA_DIR/docs/<source-id>/<slug>.<ext>；gbrain put <slug>（stdin 传内容；slug=<source-id>/docs/<name>，source-id 即 kb-<id>，与上游 slug 前缀栅栏一致）CLI 非零退出 → stderr 透传进 job.error
5 索引gbrain embed <slug>；分块/向量全部交给 gbrainembed 失败 job 标 done_with_warnings（关键词检索可用）

取舍：1 文档 = 1 页面；gbrain chunker 与检索索引强耦合，外部预分块（docling /v1/chunk）反而破坏元数据一致性，故不用。原始文件存本地 volume 而非 gbrain files storage（CLI 无删除命令，生命周期无法闭环）。

6错误处理与可观测性

  • 网关上游 401/403：自动刷新 client_credentials token 后重放一次；仍失败 → 502。
  • KB 状态：归档 → 410；不存在 → 404；key 权限外 → 403。
  • 结构化日志：stdout JSON（请求、job 生命周期、上游凭证刷新）；管理面与租户面操作均含 key 标识，满足"流量经网关 + 审计"。限流 v1 仅做 MCP 代理逐 key 并发上限（沿用 cli2api maxConcurrency 模式）。

7测试与验收

  • 集成测试（bun test 对 compose 栈）：建 KB → 签发 key（写 + 跨读组合）→ 上传 fixture PDF/图片/URL → 轮询 job → REST 检索命中内容 → MCP 会话 tools/list + get_page（越权 slug 被拒）→ federated-read 跨源命中且未授权源不可见（双源对照断言，语义已实证）→ 越权跨 KB 检索 403 → 删 KB 后归档可见。
  • cli2api 库测试沿用其现有形态：argv 映射、SSE、400/404/405、并发 429。
  • 验收口径：三个导入通道（文件/URL/MD 直传）全链路出索引；agent 只见审批组合内的分区；管理面可完成 gbrain 全量 CLI 操作。
