## User Scenarios & Testing *(mandatory)*

### User Story 1 - 集成者获取完整机器可读接口描述 (Priority: P1)

业务集成者（前端/后端开发者、网关配置者）通过稳定地址获取本服务的 OpenAPI 描述文档，内容覆盖全部对外接口：租户面（导入、检索、任务）、管理面（知识库与凭证管理）与引擎运维代理面。文档包含每个接口的路径、方法、鉴权要求、请求参数/请求体与响应形状，精度足以直接生成客户端代码或配置网关，无需人工读源码或口口相传。

**Why this priority**: 机器可读描述是契约的权威载体——接口描述与实际行为不一致时，集成成本以天计。

**Independent Test**: 拉取文档后，任选三个不同平面的接口按文档发起真实调用成功，且文档中不存在注册路由之外的虚构条目。

**Acceptance Scenarios**:

1. **Given** 服务运行中，**When** 拉取服务描述文档，**Then** 获得 OpenAPI 3.x 格式的合法 JSON，且每一平面（租户/管理/引擎代理）均有接口条目。
2. **Given** 文档已获取，**When** 按文档对任一列出的接口发起真实调用（含鉴权头），**Then** 行为与文档描述一致（成功形状或文档声明的错误码）。
3. **Given** 服务新增或下线了一个接口，**When** 重新拉取文档，**Then** 文档与实际注册路由集合完全一致（零漂移）。

---

### User Story 2 - 交互式调试界面（Swagger UI）在线试用 (Priority: P2)

开发者打开服务自带的文档页面，即可浏览全部接口并在页面内"试一试"直接执行：先填入自己的凭证（管理员令牌或租户密钥），再触发请求查看真实响应。文档站点可在部署完成后离线使用（页面与交互资源不依赖外部公共网络）。

**Why this priority**: 在线试用将"读文档"变成"验证集成"，显著缩短联调时间；自托管保证内网部署可用。

**Independent Test**: 浏览器打开文档页面，填入一枚有效凭证，对健康检查与检索接口各执行一次试用并获得真实响应，全程不访问外部网络资源。

**Acceptance Scenarios**:

1. **Given** 服务运行中，**When** 浏览器打开文档页面，**Then** 页面完整加载并可切换浏览全部接口分组（服务接口与引擎代理面）。
2. **Given** 页面已打开，**When** 在授权输入处填入管理员令牌并对健康检查执行试用，**Then** 页面内展示真实响应与状态码。
3. **Given** 部署环境无外部互联网访问，**When** 打开文档页面并执行试用，**Then** 功能完整可用（交互资源全部由本服务自提供）。

---

### User Story 3 - 文档与接口实现零漂移保障 (Priority: P3)

团队在持续集成中运行一致性校验：文档中列出的每个接口都必须真实注册，且注册的每个接口都必须出现在文档中；漂移即构建失败。这保证文档长期可信，不随迭代腐化。

**Why this priority**: 不加约束的文档会在第三次迭代后失去公信力；但它是质量闸门而非直接用户价值。

**Independent Test**: 人为在路由注册中增删一个接口后运行一致性校验，校验按预期失败并指出差异。

**Acceptance Scenarios**:

1. **Given** 文档与注册路由一致，**When** 运行一致性校验，**Then** 通过。
2. **Given** 注册中新增了一个未写入文档的接口，**When** 运行校验，**Then** 失败并指明该接口。

### Edge Cases

- 未授权访问者打开文档页面/拉取文档 → 文档默认公开可读（其内容仅为接口形状，不含数据）；部署方如需隐藏，可通过既有网络层手段处理
- 引擎代理面的文档 → 来自引擎运维代理的既有描述数据（55 路由），必须在统一文档页中可选可读，而非游离在站点之外
- 流式接口（引擎代理 SSE、MCP 网关）→ 文档如实标注其流式语义与适用客户端类型，不做非流式化伪装
- 文档地址被探测爬取 → 与健康检查同级的公开元信息，v1 不单独设防（与"文档默认公开"假设一致）
- 试一试执行写操作（如删除页面）→ 界面按既有鉴权要求执行，后果与真实调用一致（文档页不提供额外的二次确认）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在稳定地址提供 OpenAPI 3.x 格式的机器可读描述，覆盖租户面与管理面全部自有接口，含鉴权要求、请求参数/体与响应形状。
- **FR-002**: 系统必须在稳定地址提供引擎运维代理面的接口描述（复用其既有描述数据），并与服务文档在统一入口可达。
- **FR-003**: 系统必须提供自托管的交互式文档页面：浏览全部接口分组、支持录入管理员令牌/租户密钥后直接执行请求并展示真实响应；页面及交互资源不依赖外部公共网络。
- **FR-004**: 文档内容必须与实际注册路由零漂移：任何注册接口缺失于文档、或文档包含未注册条目，均视为缺陷并可被自动化校验捕获。
- **FR-005**: 流式接口（引擎代理流式输出、Agent 网关）必须在文档中如实标注流式语义。
- **FR-006**: 文档与页面默认公开可读；该默认可在评审中推翻，但推翻前按公开假设设计（不内置文档级鉴权开关）。

### Key Entities *(include if data involved)*

- **服务接口描述**: OpenAPI 3.x 文档；租户面 + 管理面；含鉴权方案定义（管理员令牌、租户密钥两种）。
- **引擎代理描述**: 引擎运维代理面的既有接口描述数据（55 路由），作为文档的第三分组。
- **文档页面**: 自托管交互界面；接口分组切换 + 凭证录入 + 在线执行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三个平面（租户/管理/引擎代理）的接口在文档中 100% 可见，抽样 3 个跨平面接口按文档调用全部成功。
- **SC-002**: 文档与注册路由集合双向一致（零漂移），并有一致性校验纳入持续集成。
- **SC-003**: 断网环境（屏蔽外部公共网络）下文档页面加载与试一试执行完整可用。
- **SC-004**: 新集成者从打开文档到首次成功调用的时间 ≤ 10 分钟（与主特性 SC-005 同口径）。

## Assumptions

- 文档与页面默认公开可读：内容为接口形状而非业务数据，与既有健康检查公开同级；如需隐藏走部署网络层。
- 引擎代理面描述直接复用其既有描述数据，不在本特性内重写。
- 一致性校验以"文档源自同一注册事实"的方式实现其可信性（实现方式归计划阶段）。
- 文档页内的"试一试"与真实调用完全等价，不提供额外确认层。

## Dependencies

- 统一路由入口（单一服务内汇聚三平面端点）。
- 引擎运维代理的既有接口描述数据。
- 交互式文档的页面资源（须可随服务自托管分发）。

## Out of Scope

- 文档级鉴权开关（默认公开假设被推翻时另行立项）
- 多版本文档并存（v1 仅描述当前版本）
- MCP 网关的 OpenAPI 化（MCP 协议不适用 OpenAPI 描述；以既有 MCP 契约文档为准）
- 代码生成模板维护（文档精度足以支撑任意外部生成器即可）
