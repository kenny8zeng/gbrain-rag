# Feature Specification: OpenAI 兼容统一模型配置（openai-compatible-model-config）

**Feature Branch**: `006-model-config-unified`

**Created**: 2026-09-03（v2：按评审决策重写——范围收缩为仅 OpenAI 兼容 API）

**Status**: Draft

**Input**: User description: "就按只支持 OpenAI 兼容 API 来做，让配置逻辑变得优雅直观——供应商概念退化为端点地址，配置最小化。"

## 背景与问题陈述

当前模型配置要求用户理解**引擎内部接入机制**：同一服务里不同能力（对话/向量化/重排）配置格式不一致（有的四个配置项、有的一个模型名加共享凭证）；有前置开关用户需自己发现、漏设时**零报错静默失效**；报错引用用户从未见过的概念。配置设计把"引擎认不认这个模型"这类内部事实暴露给了用户。

**范围决策（本特性前提）**：主流模型服务（阿里云百炼、OpenRouter、DeepSeek、OpenAI、智谱等）均提供 OpenAI 兼容 API 端点——本服务**只支持 OpenAI 兼容 API 形态**。由此"供应商"概念可完全退化为**端点地址**：用户不再需要知道任何供应商内部机制（认证名单、接入通道、端点路径、输出维度、启用开关），全部由服务自动探测与适配。

目标心智：**每个模型能力 = 三行配置：端点地址 + 纯模型名 + 钥匙**；三种能力格式完全一致；服务在配置时对端点做真实探测，把一切错误拦在配置阶段。

## User Scenarios & Testing

### User Story 1 - 端点三要素声明式配置（Priority: P1）

作为部署者，我按同一种格式配置每个模型能力：填"服务的地址 + 型号 + 钥匙"，三行一个能力，三种能力长得一模一样。我完全不需要知道服务端如何接入、接口路径长什么样、有什么开关。

**Why this priority**: 这是"优雅配置"的终态——零引擎知识、零供应商知识，只剩人人会填的三要素。

**Independent Test**: 全新部署仅凭面向用户的文档（不含任何引擎/接口内部概念）完成三项能力配置并跑通一次检索。

**Acceptance Scenarios**:

1. **Given** 一个全新部署，**When** 我按文档为对话/向量化/重排各填三行（端点+型号+钥匙），**Then** 服务启动后全部能力就绪，一次检索返回非降级结果
2. **Given** 三种能力的配置区，**When** 我横向对比，**Then** 格式与字段数完全一致（无能力特例、无额外开关、无隐藏前置）
3. **Given** 配置完成的服务，**When** 我查看配置状态，**Then** 每项能力显示"就绪"，展示语言不含任何内部接入术语

### User Story 2 - 配置时真实探测与反馈（Priority: P2）

我填错端点地址、填错型号、钥匙无效或能力缺口时，**配置当时**就得到人话错误与修正建议——服务对我的端点做真实请求来验证，而不是事后运行失败。

**Why this priority**: 消灭三类最伤信任的行为——配置看起来成功运行后才失败、漏设前置零提示、报错引用陌生概念。

**Independent Test**: 提交（a）不可达端点、（b）端点可达但型号不存在、（c）钥匙无效、（d）需服务自动判定的属性无法判定，四类配置各观察反馈。

**Acceptance Scenarios**:

1. **Given** 我填了无法连接的端点地址，**When** 配置被提交，**Then** 立即得到"端点不可达"的明确错误
2. **Given** 端点可达但型号不存在，**When** 配置被提交，**Then** 立即得到型号无效的错误（服务已探测端点返回的可用型号或真实报错）
3. **Given** 钥匙无效，**When** 配置被提交，**Then** 立即得到凭证被拒绝的错误（如可行，服务用一次最小请求验证）
4. **Given** 某项能力需要服务无法自动判定的属性（如输出维度且端点不返回），**When** 配置被提交，**Then** 服务明确询问该属性——绝不静默采用默认
5. **Given** 重排端点接口形态未知（各服务重排路径不统一），**When** 配置被提交，**Then** 服务自动探测识别，用户无需指定任何路径细节
6. **Given** 配置存在缺口（缺钥匙等），**When** 配置被提交，**Then** 返回"还缺什么"的完整清单，而非部分成功

### User Story 3 - 声明式变更与无痛迁移（Priority: P3）

换型号/换服务 = 改对应的行；已用旧格式配置的部署升级后原样工作。

**Why this priority**: 降低模型决策的变更成本；保护既有用户。

**Independent Test**: （a）同端点换型号 → 全链路验证；（b）整体切换到另一家 OpenAI 兼容服务（改三行+钥匙）→ 验证；（c）旧格式部署升级 → 行为不变。

**Acceptance Scenarios**:

1. **Given** 已配置向量化能力，**When** 我改型号为同端点另一型号，**Then** 无需改其他配置即完成切换（服务重新探测并提示数据影响如向量重建）
2. **Given** 已配置完成，**When** 我把某能力切换到另一家服务（改端点+型号+钥匙三行），**Then** 配置完成；唯一附加提示是"切换向量化模型将重建已有向量索引"（数据成本告知，非配置负担）
3. **Given** 旧格式配置的现有部署，**When** 升级到新版本，**Then** 原配置原样生效（零迁移、无弃用风暴）

### Edge Cases

- 同一端点服务三个能力（如一个兼容网关同时代理对话/向量化/重排）→ 端点与钥匙可复用，服务按能力各自探测
- 端点可达但能力不支持（如某端点只代理对话，不支持向量化）→ 配置该能力时立即报"该端点不支持向量化"（探测证据），非运行期失败
- 运行期模型被服务商下架（配置时无法预知）→ 调用失败时给出可操作提示（含最近可用型号建议），非技术性报错
- 新旧格式并存且矛盾 → 文档化优先级 + 状态查询提示冲突（不静默）
- 只配置部分能力 → 未配置能力明确显示"未配置"及影响说明（哪类检索降级），不报错

## Requirements

### Functional Requirements

- **FR-001**: 每个模型能力（对话/向量化/重排）的配置 MUST 仅含三要素：端点地址、纯模型名、凭证——格式与字段数三种能力完全一致
- **FR-002**: 模型名 MUST 以纯名称填写（无任何前缀/供应商标记/接口细节）
- **FR-003**: 服务 MUST 只对接 OpenAI 兼容 API 形态；非兼容服务不在支持范围（文档声明）
- **FR-004**: 端点地址、型号、凭证的可用性 MUST 在配置提交时经真实请求验证并即时反馈（不可达/型号无效/凭证被拒/能力不支持，均给出人话错误）
- **FR-005**: 服务能自动探测判定的属性（重排接口形态、输出维度等）MUST 自动处理，用户无需提供任何接口路径或机制细节
- **FR-006**: 无法自动判定的必需属性 MUST 明确询问，禁止静默采用默认值
- **FR-007**: 配置缺口 MUST 返回完整清单（缺什么、在哪填）
- **FR-008**: 配置状态 MUST 随时可查（每能力：就绪/未配置/有缺口/探测失败+原因），面向用户语言
- **FR-009**: 端点与凭证 MUST 可跨能力复用（同一服务多个能力共用一套时不必重复填写）
- **FR-010**: 旧格式配置 MUST 继续有效（向后兼容，零迁移）
- **FR-011**: 新旧格式并存冲突 MUST 有文档化优先级并在状态中提示
- **FR-012**: 更换型号/服务 MUST 为声明式单点变更；数据影响（向量重建）以告知形式出现，不增加配置步骤
- **FR-013**: 运行期模型不可用 MUST 给出可操作提示（含可切换建议），非技术性报错

### Key Entities

- **能力（Capability）**: 对话、向量化、重排；各自独立配置与状态
- **端点（Endpoint）**: OpenAI 兼容服务的地址（用户所购服务的 URL）；携带凭证时可跨能力复用
- **模型（Model）**: 端点上可用的型号；用户以纯名称引用
- **凭证（Credential）**: 端点的访问钥匙
- **配置状态（Configuration State）**: 每能力×要素的就绪度与探测结果，供状态查询

## Success Criteria

### Measurable Outcomes

- **SC-001**: 新用户仅凭面向用户的文档（不含任何引擎/接口内部概念）在 10 分钟内完成三项能力配置并通过一次检索
- **SC-002**: 配置错误（端点不可达/型号无效/凭证被拒）在配置提交时被拦截的比例 100%——不存在"配置成功、运行后才失败"的配置期错误
- **SC-003**: 配置文档中机制/内部概念讲解占比下降 80%（对照当前 recipe/白名单/端点路径等说明篇幅）
- **SC-004**: 用户更换型号或服务只需修改对应三行（端点/型号/钥匙），无额外配置步骤
- **SC-005**: 升级到新版本的用户中需手动迁移配置的比例为 0

## Assumptions

- 支持范围 = OpenAI 兼容 API 服务（含各家兼容模式与聚合网关）；原生独有 API 形态不在 v1 范围（用户可自行经兼容网关接入）
- 配置时探测以最小代价真实请求实现（一次小请求验证端点/型号/凭证；探测失败给出明确原因）
- 自动判定失败的属性极少且可用明确询问兜底
- 配置入口为环境变量与状态/配置 API 两类（现有部署形态），本特性不引入新载体
- 已有配置兼容为硬性要求
