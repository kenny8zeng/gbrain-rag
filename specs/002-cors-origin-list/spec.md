# Feature Specification: 可选的跨域来源列表（CORS）

**Feature Branch**: `002-cors-origin-list`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "支持可选的跨域列表"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览器前端应用直连服务 (Priority: P1)

业务前端（运行在浏览器中的网页应用）需要直接调用本服务的接口，而不必自建代理转发。管理员在部署时配置一份"允许的来源列表"（例如前端站点地址）；列表内来源的浏览器请求被放行，浏览器因此允许网页读取响应。列表之外的来源一律不放行。

**Why this priority**: 没有跨域放行，所有浏览器直连场景（前端检索组件、Agent 调试面板）都无法落地，这是本特性的核心价值。

**Independent Test**: 配置含某来源的列表后，用该来源发起跨域请求能读到响应；用未列入来源发起同样请求读不到，即验证完成。

**Acceptance Scenarios**:

1. **Given** 列表含来源 `https://app.example.com`，**When** 该来源的页面预检并调用检索接口，**Then** 预检通过且响应携带放行标记，浏览器可读取数据。
2. **Given** 同一配置，**When** 来源 `https://evil.example.com` 发起同样请求，**Then** 响应不携带任何放行标记，浏览器拒绝读取。
3. **Given** 需要携带自定义请求头的接口调用，**When** 列表内来源发起预检，**Then** 预检响应声明允许该请求头与方法。
4. **Given** 未配置列表（默认），**When** 任意来源发起跨域请求，**Then** 响应不携带放行标记（行为与特性上线前完全一致）。

---

### User Story 2 - 部署方按环境控制放行范围 (Priority: P2)

管理员可以在部署配置中维护来源列表：增删来源后重启（或按配置生效机制刷新）即生效；列表语法支持逐条枚举来源，也支持显式声明"放行全部来源"（以星号值表达，仅供内网/受信环境选用）。配置为空时特性整体关闭。

**Why this priority**: 让放行范围成为部署决策而非代码决策，是"可选"二字的落点；也为受信内网提供免枚举的开关。

**Independent Test**: 修改配置中的列表内容并重启后，放行行为随之变化，可通过接口响应头直接观察。

**Acceptance Scenarios**:

1. **Given** 列表为空，**When** 检查任意跨域响应，**Then** 不存在放行标记。
2. **Given** 列表配置为"放行全部"显式值，**When** 任意来源发起请求，**Then** 响应携带全放行标记。
3. **Given** 列表含三条来源，**When** 移除一条并重启后请求该来源，**Then** 该来源不再被放行。

### Edge Cases

- 来源带端口/路径变体（如 `https://app.example.com:8443`）→ 按浏览器来源语义精确匹配（协议+域名+端口整体一致），路径部分忽略
- 预检请求本身（浏览器自动发出的无凭证探测）→ 必须被放行逻辑响应，不得要求业务鉴权头
- 非浏览器客户端（服务端间调用、命令行工具）→ 不受任何影响，行为与跨域特性无关
- 列表含非法条目（空串、非来源格式）→ 启动时校验拒绝并明确指出非法条目
- 放行全部与逐条枚举混用 → 以最宽语义生效，并在配置文档中说明

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持部署级"跨域来源列表"配置；列表为空（默认）时，系统行为与未实现跨域特性时完全一致（不产生任何放行标记）。
- **FR-002**: 列表非空时，系统必须对所有对外 HTTP 端点（业务接口、文档页、健康检查、Agent 网关端点）统一生效。
- **FR-003**: 系统必须按浏览器来源语义（协议+域名+端口整体）精确匹配请求来源；列表支持显式"放行全部"星号值，选用时对任意来源生效。
- **FR-004**: 列表内来源发起的跨域请求，其响应必须携带浏览器要求的放行标记（允许的来源回显、允许的方法与请求头、预检有效期）；放行方法至少覆盖查询、提交与取消类操作所需。
- **FR-005**: 浏览器预检探测必须被直接应答（不缺失放行标记、不要求业务鉴权头），且预检处理不得触发业务副作用。
- **FR-006**: 列表变更后按配置生效机制（重启或配置刷新）应用；非法配置条目必须在启动时被拒绝并指明条目。
- **FR-007**: 放行判断与标记生成必须对非浏览器客户端零影响（无来源头的请求行为不变）。

### Key Entities *(include if data involved)*

- **来源列表（部署配置项）**: 字符串数组；元素为浏览器来源（协议+域名+端口）或全放行星号值；空数组 = 特性关闭。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 列表内来源的浏览器调用 100% 可被网页读取（预检 + 实际请求均携带正确放行标记）。
- **SC-002**: 列表外来源 100% 不携带放行标记（抽取不少于 3 个未列入来源验证）。
- **SC-003**: 列表为空时，跨域相关响应头出现率为 0，且既有接口的响应时延无可测劣化。
- **SC-004**: 预检请求在 200 毫秒内获得应答（本地部署环境采样）。

## Assumptions

- 默认列表为空 = 特性关闭；"放行全部"（星号）是显式选入值，文档标注仅建议受信内网使用。
- 认证采用请求头携带密钥而非 Cookie，因此放行标记无需携带"允许凭证"语义；浏览器端调用与其他普通请求一致。
- 列表来源的变更通过重启应用生效（与既有部署配置一致）；热刷新不做。
- 跨域语义仅作用于浏览器场景；服务端到服务端调用不受影响。

## Dependencies

- 既有统一路由入口（所有对外 HTTP 端点汇聚于单端口服务，跨域处理覆盖全部端点）。
- 部署配置机制（环境变量模板）。

## Out of Scope

- Cookie/会话型凭证的跨域放行
- 来源列表的运行时管理接口（列表属部署配置，不入库、不进管理面 API）
- 通配符子域名匹配（如 `*.example.com`）
- 代理层（反向代理/网关）上的跨域处理
