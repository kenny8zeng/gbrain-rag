# Feature Specification: 梦境周期调度（dream-cycle-scheduler）

**Feature Branch**: `007-dream-cycle-scheduler`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "增加环境变量来配置 supervisor 调 dream 的定时和成本，确认是否有手工启动梦境周期的 API，如果梦境周期在执行，新的启动请求要拒绝。"

## 背景与问题陈述

知识库引擎的"梦境周期"（隔夜维护：关系提取/反思合成/索引整理）当前是纯命令形态（cron-friendly），部署中**没有调度器调用它**——知识库不会自动建图/维护；也**没有 HTTP 入口**让管理员按需触发；且若周期任务被并发触发（定时 + 手工同时），会叠跑浪费算力与模型成本。

目标：把梦境周期接入服务生命周期——**环境变量配置调度与成本档**、**管理面 API 手工触发**、**执行中互斥（新触发被拒绝）**，让部署者按需自动或手动维护知识图谱，成本可控、不叠跑。

## User Scenarios & Testing

### User Story 1 - 部署者配置定期梦境（Priority: P1）

作为部署者，我用环境变量开启定期梦境周期并选成本档：不配置则完全关闭（现状）；配置即按周期自动运行。成本档决定周期做多少事（轻量 = 只做关系提取建图，不跑耗模型的反思合成；完整 = 全部维护阶段）。

**Why this priority**: 让"知识库自动建图/维护"成为可配置默认能力，且成本透明可控——这是本特性的核心价值。

**Independent Test**: 配置"每 6 小时轻量档"后，观察服务在预期时刻触发一次梦境（日志事件），运行完成后知识库出现自动提取的关系边；未配置时确认零触发。

**Acceptance Scenarios**:

1. **Given** 未配置任何梦境环境变量，**When** 服务运行 24 小时，**Then** 不执行任何梦境周期（零触发、零模型消耗）
2. **Given** 配置"间隔 6 小时 + 轻量档"，**When** 服务运行跨越两个周期点，**Then** 恰好触发 2 次且每次日志有开始/完成事件
3. **Given** 轻量档的周期完成，**When** 检查知识库，**Then** 出现自动提取的关系边（图从空变为非空），且无反思合成类页面生成（LLM 高耗步骤未跑）
4. **Given** 本特性交付，**When** 对照用户文档（部署/使用/认证/README），**Then** 新环境变量、管理面接口、错误码、特性描述均已同步（中英 README 同构）

### User Story 2 - 管理员手工触发（Priority: P1）

作为管理员，我可以随时经管理面接口手工启动一次梦境周期（不必等定时点），接口异步返回、不阻塞其他请求。

**Why this priority**: 手工触发是"我要现在就建图/维护"的直接手段——与定时互补。

**Independent Test**: 管理面发起一次触发 → 得到已接受响应 → 随后日志出现梦境执行；非管理员调用被拒。

**Acceptance Scenarios**:

1. **Given** 管理员身份，**When** 调用手工触发接口，**Then** 请求被接受（异步执行，响应含运行标识），服务其他接口不受影响
2. **Given** 非管理员（租户 key/无凭证），**When** 调用触发接口，**Then** 被拒绝（401/403）
3. **Given** 手工触发执行中，**When** 查询状态，**Then** 状态显示"运行中"

### User Story 3 - 执行中互斥拒绝（Priority: P2）

梦境周期正在执行时，任何新的启动请求（定时点到或再次手工触发）都被拒绝并说明已有周期在运行——绝不叠跑。

**Why this priority**: 防叠跑 = 防算力与模型成本翻倍；状态可见让运维理解拒绝原因。

**Independent Test**: 启动一次（手工或触发长运行场景）后立即再触发 → 第二次被拒绝且响应指明已有运行；运行结束后再次触发成功。

**Acceptance Scenarios**:

1. **Given** 梦境周期运行中，**When** 管理员再次手工触发，**Then** 请求被拒绝（明确错误码与"已有运行"信息）
2. **Given** 梦境周期运行中且定时点到达，**When** 周期调度器到点，**Then** 跳过本轮（不叠跑），运行结束后下轮恢复
3. **Given** 服务重启时恰有梦境在跑（异常中断），**When** 服务恢复，**Then** 锁状态不残留导致永久拒绝（有超时/恢复机制）

## Requirements

### Functional Requirements

- **FR-001**: 梦境周期 MUST 可通过环境变量启用与配置调度间隔（默认关闭；开启后按配置间隔自动触发）
- **FR-002**: 成本档 MUST 可配置：至少"轻量"（仅关系/时间线提取，不跑 LLM 反思合成）与"完整"（全部维护阶段）两档；默认轻量
- **FR-003**: 调度触发 MUST 由服务内部执行（与 HTTP 服务同进程生命周期），不依赖外部 cron
- **FR-004**: 管理面 MUST 提供手工触发接口（异步接受、返回运行标识）；非管理面 MUST 拒绝
- **FR-005**: 状态查询 MUST 可见：上次运行结果（时间/成功失败/关键计数）、当前是否运行、下次计划时间
- **FR-006**: 运行中互斥 MUST 成立：执行中任何新触发（手工或定时）被拒绝；定时到点跳过本轮
- **FR-007**: 互斥锁 MUST 有恢复机制：异常中断（进程重启）后不永久锁死（运行超时上限/启动时清理孤儿态）
- **FR-008**: 执行过程 MUST 可观测：开始/完成/失败/被拒均有日志事件；失败不影响服务其他功能
- **FR-009**: 梦境执行 MUST 不影响摄取/检索可用性（异步、与请求处理解耦；资源竞争由调度间隔承担并在文档说明）
- **FR-010**: 触发执行 MUST 走引擎既有周期命令（不绕过引擎实现），阶段与档位映射到命令参数
- **FR-011**: 交付 MUST 同步全部对应用户文档：部署文档环境变量全表（新 env 的键/默认/档位说明）、使用文档管理面路由表与错误码表（手工触发/状态查询/运行中拒绝）、认证文档管理面覆盖清单、README 特性与配置要点（中英同构同步修改）

### Key Entities

- **梦境周期配置（Dream Schedule Config）**: 环境变量表达——启用、间隔、成本档；部署期设定
- **梦境运行（Dream Run）**: 一次周期执行；标识、开始/结束时间、阶段、结果（计数/错误）
- **运行锁（Run Lock）**: 互斥状态——运行中标记 + 超时恢复；防并发叠跑
- **成本档（Cost Tier）**: 轻量（关系提取，无 LLM 合成）/ 完整（全阶段，含 LLM 反思合成）

## Success Criteria

### Measurable Outcomes

- **SC-001**: 配置开启后，周期按配置间隔自动触发（24h 内触发次数与间隔一致，误差 ≤1 次）；未配置零触发
- **SC-002**: 轻量档运行后知识库图边数从 0 变为 >0（自动提取生效）；完整档含反思合成输出
- **SC-003**: 运行中并发触发的拒绝率 100%（无任何叠跑——同时最多一个运行）
- **SC-004**: 管理员手工触发从调用到接受 ≤2s（异步返回）；非管理员 100% 拒绝
- **SC-005**: 异常中断后服务恢复，锁在 ≤1 个周期内自愈（不永久拒绝新触发）
- **SC-006**: 交付后用户文档与实现一致：部署/使用/认证文档中的新 env、接口、错误码均可在实现中找到对应且描述相符；README 中英两版均含本特性（无单语遗漏）

## Assumptions

- 间隔以小时为单位配置（覆盖每日/数小时粒度；分钟级不做——维护周期无此需求）；默认关闭（零行为变化，向后兼容）
- 成本 = 频率 × 档位（阶段集）；档位决定是否跑 LLM 反思合成——具体模型与内部预算沿用引擎配置面（本特性不引入新模型配置）
- 手工触发与定时触发共享同一运行锁；执行异步（后台），HTTP 立即返回
- **梦境 LLM 复用主对话配置**（用户已配的端点三要素自动适配）：v1 不引入梦境独立模型配置面——引擎按用途分模型的内部机制（门控/合成键）对用户不可见，不出现在任何用户文档；成本差异由成本档（light 无 LLM / full 复用主对话）承载。未来若出现"梦境需用不同模型"的真实需求，按既有"每能力三要素"同构格式扩展，而非现在预置第四组配置
- 互斥锁存于进程内 + 运行超时上限（跨重启清理：启动时若存在超龄孤儿运行标记则清除）；多副本部署下锁语义为"本实例内互斥"（单实例部署为现实目标，多副本互斥不在 v1）
- 触发执行复用引擎既有命令，阶段映射：轻量=关系/时间线提取；完整=周期全阶段
- 文档同步为交付一部分（非后续）：涉及 docs/deployment.md（env 表）、docs/usage.md（管理面路由/错误码）、docs/auth-model.md（管理面覆盖）、README 中英两版；文档语言口径沿用仓库惯例（docs 中文、README 双语同构）
