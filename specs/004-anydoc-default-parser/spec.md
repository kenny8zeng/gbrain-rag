# Feature Specification: anydoc 作为默认文档解析器

**Feature Branch**: `004-anydoc-default-parser`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "使用 anydoc 作为项目的默认文档解析方案，在环境变量中 docling 配置项为空时默认使用 anydoc 作为默认解析实现。"

## 背景依据

gbrain 知识库对 anydoc 的实测评估（`tools/anydoc-firecrawl`，2026-09-02，46 份真实中文文档 62MB）：成功率 45/46（97.8%），docx/doc/xlsx/csv/pptx/文本型 PDF 优秀至良好；公式/嵌套表格/双栏 PDF 不佳；本地无 OCR（扫描 PDF 报 `needsOcr`）。性能：docx 12.9ms、pdf 725KB 192ms 热调用中位，进程内 native 转换（Bun 实测可用，`@firecrawl/anydoc`）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 未配置外部解析服务时，文件导入开箱即用 (Priority: P1)

部署方只配置知识库所需的最少环境（不填任何外部文档解析服务地址）时，上传 Office/PDF/EPUB/CSV 等文档文件仍可正常导入：异步任务完成转换 → 页面入库 → 检索可用。转换在服务进程内毫秒级完成，不依赖外部网络。

**Why this priority**: 消除对单一外部解析服务的硬依赖，是"默认解析方案"的核心价值；anydoc 评估证明其覆盖绝大多数办公文档且质量达标。

**Independent Test**: 不配置外部解析服务地址部署 → 上传 docx 与文本型 PDF → 任务 done → 检索命中内容。

**Acceptance Scenarios**:

1. **Given** 未配置外部解析服务，**When** 上传 Word 文档，**Then** 任务成功且页面内容完整可检索。
2. **Given** 未配置外部解析服务，**When** 上传文本型 PDF，**Then** 任务成功且内容可检索。
3. **Given** 未配置外部解析服务，**When** 上传表格类文档（xlsx/csv），**Then** 表格内容转为 Markdown 且可检索。
4. **Given** 已配置外部解析服务（docling），**When** 上传文档，**Then** 行为与现状一致（外部服务路径不受影响）。

---

### User Story 2 - 外部服务独有能力在未配置时得到明确指引 (Priority: P1)

网页 URL 导入与独立图片导入依赖外部解析服务的能力；当外部服务未配置（默认解析器模式）时，这两类请求不再静默失败或走错误路径，而是返回明确的错误指引：告知该能力需要配置外部解析服务地址。

**Why this priority**: 保持接口契约的诚实性——不支持就明确说，而非含糊报错；避免调用方误以为内容已入库。

**Independent Test**: 默认解析器模式下分别提交 URL 与图片 → 均得到指明"需配置外部解析服务"的明确错误。

**Acceptance Scenarios**:

1. **Given** 默认解析器模式，**When** 提交网页 URL 导入，**Then** 请求被明确拒绝并提示该能力需配置外部解析服务。
2. **Given** 默认解析器模式，**When** 上传独立图片文件，**Then** 同上明确拒绝。
3. **Given** 已配置外部解析服务，**When** 提交 URL 或图片，**Then** 与现状一致正常处理。

---

### User Story 3 - 扫描 PDF 的处置语义 (Priority: P2)

默认解析器本地无法读取扫描型（纯图像）PDF——任务失败并给出可读原因（"扫描型 PDF，需 OCR"），不产生半成品页面；部署方如提供可选 OCR 密钥，则扫描 PDF 自动走托管 OCR 后正常入库。

**Why this priority**: 评估中唯一失败样本即扫描 PDF；明确失败原因与可选升级路径，避免运维困惑。

**Independent Test**: 默认模式上传扫描 PDF → failed 且原因含 OCR 指引；配置可选密钥后重传 → done。

**Acceptance Scenarios**:

1. **Given** 默认解析器模式，**When** 上传扫描型 PDF，**Then** 任务 failed，错误信息明确指出"扫描 PDF 需 OCR"且不残留半成品页面。
2. **Given** 部署配置了可选 OCR 密钥，**When** 上传同一扫描 PDF，**Then** 任务成功。
3. **Given** 上传损坏/加密/不支持格式文件，**Then** 任务 failed 且错误原因分类明确（对应解析器错误分类）。

### Edge Cases

- 无扩展名/签名不明确的文件（如纯 CSV 无签名）→ 按内容嗅探失败时给出明确格式错误
- 超大文档（>50MB Office / >20MB PDF）→ 不阻塞 worker（转换在 worker 内，受既有任务超时约束）
- docling 与默认解析器均不可用时 → 文件导入明确报"无可用解析实现"
- 默认解析器模式下健康检查的外部解析服务状态 → 如实显示"未配置"而非故障

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在外部解析服务地址配置为空时，自动启用内置默认解析器处理文档文件导入（Word/PowerPoint/Excel/OpenDocument/RTF/EPUB/CSV/文本型 PDF）。
- **FR-002**: 配置了外部解析服务地址时，文件导入行为与现状完全一致（外部服务优先，默认解析器不介入）。
- **FR-003**: 默认解析器模式必须保持既有导入契约：异步任务、前端注入、slug 派生、重复导入覆盖更新、失败重试与原因记录。
- **FR-004**: 网页 URL 导入与独立图片导入在默认解析器模式下必须被明确拒绝，错误信息指明该能力需配置外部解析服务地址。
- **FR-005**: 扫描型 PDF 在默认解析器模式下必须失败并给出可读原因（OCR 提示），不得残留半成品页面；部署方配置可选 OCR 凭证后必须自动走托管 OCR 成功导入。
- **FR-006**: 文件内容无法识别/损坏/加密时，任务失败原因必须按解析器错误分类给出明确指引。
- **FR-007**: 默认解析器模式下健康检查必须如实反映外部解析服务"未配置"状态（非故障）。

### Key Entities *(include if data involves)*

- **解析器选择**: 部署配置决定：外部解析服务地址非空 → 外部服务路径；为空 → 内置默认解析器（文件类）。
- **默认解析器错误分类**: 映射自内置解析器错误码（不支持格式/需 OCR/损坏/加密/超限等）→ 任务失败原因文案。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 默认模式下 Office 与文本型 PDF 导入成功率 ≥ 95%（以 20 份以上真实样本计；评估基线 97.8%）。
- **SC-002**: 默认模式下典型文档（docx ≤10MB）从提交到可检索的端到端耗时 ≤ 60 秒（P95，含轮询粒度）。
- **SC-003**: URL 与图片导入在默认模式下 100% 返回指向"需配置外部解析服务"的明确错误（不产生任务或半成品）。
- **SC-004**: 既有 docling 配置路径的全部测试零回归（含契约与集成）。
- **SC-005**: 扫描 PDF 失败原因 100% 含 OCR 指引；配置 OCR 凭证后同类文件导入成功。

## Assumptions

- 内置默认解析器以进程内库形式集成（非独立服务），随服务镜像分发；其平台兼容性以官方预编译产物为准。
- 托管 OCR 属可选能力：默认关闭（数据不出机器），仅当部署方显式配置 OCR 凭证时启用——与既有"URL 导入仅限受信环境"的安全姿态一致。
- 图片嵌入文档（Word/PPT 内嵌图）由内置解析器按既有语义处理（alt 文本渲染），不受"独立图片导入"限制影响。
- 解析质量边界沿用评估结论：公式/嵌套表格/复杂双栏 PDF 不建议走默认解析器（可用外部服务路径）。

## Dependencies

- 内置解析器的 Node/Bun 绑定包（评估确认 Bun 实测可用）。
- 既有摄取管道（任务/写入/索引/检索）与错误处理机制。

## Out of Scope

- 用内置解析器替代网页抓取与图片 OCR（该能力仍归属外部解析服务）
- 内置解析器的公式/复杂版面增强（质量边界沿用评估）
- 解析器热切换（配置变更经重启生效，与既有配置机制一致）
